# styles/design-system.md

> Parent index: [`../README.md`](../README.md)

Everything visual is generated from **one fluid scaling engine**, then a set of
design tokens, then per-component CSS. This file documents that system so you can
tune the look without guessing.

---

## 1. The fluid scaling engine (the most important system)

The original site sizes itself off the browser **window** width, not a fixed breakpoint set.
The whole page "breathes" continuously with viewport.

Defined in `styles/tokens.css` `:root`:

```css
--size-unit: 16;                 /* nominal px per em */
--size-container-ideal: 1920;    /* design canvas width */
--size-container: clamp(992px, 100dvw, 3840px);
--size-font: calc(var(--size-container) / (1920 / 16));
```

**`--size-font` is the backbone.** Setting `body { font-size: var(--size-font) }`
means `1em === (container/120)` px. Because every size token is an `em`, and em tracks
the font, **everything scales when the viewport scales** — headings, margins, spacing,
borders, widths, and the container grid.

> Derivation: at 1920px → font-size 16px. Frames the "container = 120em" layout used
> by the original.

**Ultrawide cap** (`.min-width: 992px` and `min-aspect-ratio: 11/5`): the design canvas
locks to 16:9 (`--size-container-fluid: min(100dvw, calc(100dvh * 16 / 9))`) so spread
monitor didn't stretch the layout.

## 2. Breakpoints re-point the engine

Breakpoints do **not** add layout rules; they **re-make the scale**. Each one redefines
`--size-container-*` and the spacing/tokens so the fluid system re-targets.

| Breakpoint | `--size-container-ideal` | Headline step (the biggest — heading-xxl) |
|------------|--------------------------|---------------------------------------------------|
| ≥ 992px (desktop) | 1920 | `heading-xxl: var(--size--112px)` |
| ≤ 991px (landscape/tablet) | 991 | `heading-xxl: --size--112px`, heading-l/m shrink |
| ≤ 767px (portrait/tablet) | 767 | `heading-xxl: --size--96px` |
| ≤ 479px (phone) | 479 | hard-coded `3.5em` etc. |

Spacing tokens shrink per-breakpoint too (`--space-*`).

## 2. Design tokens

### Colors (`--swatch-*` → `--theme-*`)
| Swatch | Value | Used for |
|--------|-------|----------|
| `--swatch--off-white` | `#e5e5e5` | base page background (`--theme--background`) |
| `--swatch--black` | `#000` | body/heading text |
| `--swatch--grey` | `#a8a8a8` | borders |
| `--swatch--grey-40` | `#0000000f` | subtle fills |
| `--swatch--indigo` | `#0f00b0` | the System/blue section + nav theme |
| `--swatch--indigo-light` | `#2b1add` | hover/interaction variant |
| `--swatch--olive` | `#c7beaa` | the Pricing/tan section + nav theme |
| `--swatch--olive-dark` | `#aca086` | nav outline variant |

Theme classes (`.theme-base`, `.theme-indigo`, `.theme-olive`) swap `--theme--nav-*`
aliases so **nav and sections share color state** from one source.

### Size tokens (`--size--<px>`)
`--size--16px: 1em` … `--size--256px: 16em`. All em-based, all scale fluidly.

### Headline tokens (`--heading-*--font-size`)
* `heading-xxl` (huge, menu), `xl`, `l` (hero), `m` (block text), `s`, `xs`.
* Fonts: `--font-heading` / `--font-paragraph` both → `"PPFrama", Arial, sans-serif`
  (generated by the `@font-face` in `tokens.css` from `public/fonts/PPFrama-Regular.woff`).

### Layout
```
--page-padding: 2em      --container-padding: 1em   --grid-gap: 2em
--space-xs: 2.5vh        --space-s: 5vh   --space-regular: 8vh
--space-m: 20vh          --space-l: 25vh  --space-xl: 30vh  --space-xxl: 34vh
```
> `--space-*` are **viewport-height driven** (`vh`) — page rhythm depends on screen
> height, not width, and these are what create the section "scroll legs".

### Motion (CSS side)
```
--ease-main: cubic-bezier(.625,.05,0,1)   --elastic-ease-out: cubic-bezier(.34,1.56,.64,1)
```

## 3. CSS layers & their role

Loaded in exact order in `src/main.jsx`:

```
import "./styles/tokens.css";    // 1. design tokens + engine + breakpoints + theme classes
import "./styles/base.css";      // 2. reset, typescale classes, primitives, [space-*], underlines
import "./styles/components.css";// 3. component blocks in page order
```

### `base.css`
- Global reset (`* { box-sizing… margin:0; padding:0 }`), body setup (font, bg, font-size
  engine), selection color, hidden scrollbar.
- **Typescale** applicable-style classes: `.heading-xxl … .heading-xs`, `.paragraph-*`,
  `.text-align-*`, `.hide-tablet-mobile`, `.opacity-64`.
- **Layout primitives**: `.container` (max-width + centering), `.container-right`,
  `.padding-global`.
- **Spacing attribute system** — the site's rhythm: element-attribute-driven, viewed
  as `[space-top="xl"] { margin-top: var(--space-xl) }`, `[space-bottom="…"]`,
  `[space="…"]` (block). Any section wrapper can opt into rhythm via an attr.
- **Text-indent grid**: `[text-indent="2"]` shifts text right by N grid columns
  (the editorial "hang indent").
- **Underline link system** (hover slide).

### `components.css`
One "window" per component, in page order: NAV → FULLSCREEN MENU → HERO → MAIN BUTTON →
MAIN BTN interaction → TABS/CROPMARKS → CHAPTER → LOGO → ABSOLUTE LINK → TEXT SECTION →
SHUTTER → SYSTEM → SYSTEM VISUAL (pinned scrub) → HOW → DIFFERENT → PRICING → FOOTER →
MODAL → UTILITY → BREAKPOINT ADJUSTMENTS.

- `body` text/bg color flows from `--theme--*`.
- Fixed nav, sticky positioning for pin, transforms for pinned scenes.
- The `data-*` hooks that the JS animations query (see `animations.md`).

### `tokens.css`
Everything in §1–2 plus the theme classes (end of file).

> **Always add a new component**: `base.css` primitives + `components.css` block. Never
> hard-code a color/pixel — route through tokens.

## 4. Spacing guidance (the `[space]` notation)

Rough size meaning (desktop → mobile):

| Token | Desktop | Mobile (≤ 479) | Feel |
|-------|---------|----------------|------|
| `xs` | 2.5vh | 2vh | tiny gap |
| `s` | 5vh | 4vh | small |
| `regular` | 8vh | 6vh | default |
| `m` | 20vh | 8vh | medium |
| `l` | 25vh | 12vh | large |
| `xl` | 30vh | 15vh | section separation |
| `xxl` | 34vh | 15vh | the biggest interval before a color section |

When you want a section to feel "rooms", pick from `m`–`xxl`. For in-component rhythm
pick `normal`–`s`.

The **shutter seam bug** arises from these `[space-bottom]` margins collapsing between
sections — see `architecture.md` § "Flush sections & shutter seam".

## 5. Accessibility motion guardrails

- `prefers-reduced-motion: reduce` is read by `System.jsx`, `How.jsx`, `Different.jsx`,
  `useScramble.js` and the shutter; they short-circuit to static states.
- `button/focus-visible` outlines, `aria-expanded`/`aria-label` on interactive icons,
  and a `::selection` that follows `--theme--cursor-select-*`.
